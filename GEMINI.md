# Gemini Project Overview: Go Marketplace

This document provides a technical overview of the **Go Marketplace** project to help you understand the codebase structure, patterns, and technologies used.

## 🚀 Project Overview

**Go Marketplace** is a high-performance e-commerce backend built with Go and the Fiber v2 framework. It follows a clean, feature-based architecture designed for scalability and maintainability.

## 🏗 Architecture & Patterns

The project follows a **Feature-Based Architecture**. Each domain (e.g., `auth`, `order`, `product`, `wallet`) is encapsulated in its own package under `internal/core/`.

### Core Layers (per feature)

1.  **Handler (`*_handler.go`)**:
    *   HTTP layer using [Fiber v2](https://gofiber.io/).
    *   Responsible for request parsing, validation (using DTOs), and calling the service layer.
    *   Uses `common.NewResponse` for standardized JSON responses.
2.  **Service (`*_service.go`)**:
    *   Contains the core business logic.
    *   Defines the `*ServiceInterface` and consumes `*Repository` interfaces.
    *   Orchestrates data flow between repositories and other services.
3.  **Repository (`*_repo.go`)**:
    *   Data access layer using [sqlx](https://github.com/jmoiron/sqlx).
    *   Implements SQL queries for PostgreSQL.
4.  **DTO (`*_dto.go`)**:
    *   Defines request and response structures (Data Transfer Objects).
    *   Often includes `Validate()` methods for input validation.
5.  **Mocks (`mock_*.go`)**:
    *   Generated by [mockery](https://github.com/vektra/mockery) for unit testing.

### Shared Layers

*   `internal/domain/`: Contains shared entities (structs with `db` tags) and global error definitions (`errors.go`).
*   `internal/common/`: Shared utilities like the `ResponseWrapper`.
*   `internal/middleware/`: Custom Fiber middlewares (e.g., JWT authentication).
*   `internal/database/`: Database connection setup and migrations.
*   `internal/server/`: Router initialization and server startup logic.

## 🛠 Tech Stack

*   **Language**: Go (v1.25.8+)
*   **Web Framework**: Fiber v2
*   **Database**: PostgreSQL (via `sqlx` and `pgx`)
*   **Search Engine**: PostgreSQL Vector Search (pgvector) via `pgvector-go`
*   **Auth**: JWT (RS256/HS256) + Supabase Social Login integration.
*   **Migrations**: golang-migrate
*   **Testing**: testify, sqlmock, mockery.

## 🔑 Key Features & Logic

*   **Authentication**: Supports local email/password and social login (Supabase). Uses a refresh token family pattern for secure session rotation.
*   **Wallet System**: Internal digital wallet with transaction history.
*   **Merchant System**: Users can register shops and manage products.
*   **Product Search**: Leverages PostgreSQL full-text search and pgvector for advanced semantic queries.

## 🧪 Testing Strategy

1.  **Unit Tests**: Located alongside the code (e.g., `auth_service_test.go`). Uses mocks to isolate logic.
2.  **Integration Tests**: Located in `test/integration/`. Tests the repository layer against a real database (often using Docker).

## 💡 Tips for Working on this Codebase

*   **Error Handling**: Always use or add errors to `internal/domain/errors.go` to maintain consistency.
*   **Dependency Injection**: Use constructors (`New*`) and interfaces. When adding a new dependency to a service, update its constructor and the wiring in `internal/server/routes.go` (or wherever it's initialized).
*   **Database Queries**: Use `sqlx` named queries (`NamedExecContext`) for inserts/updates and `GetContext`/`SelectContext` for fetches.
*   **API Docs**: Maintain Swagger comments in handlers. Run `make swagger` to update documentation.
*   **Standardized Responses**: Always return `common.NewResponse(c, status, message, data)`.

## 📂 Directory Structure

```text
.
├── cmd/api/            # Application entry point (main.go)
├── internal/
│   ├── common/         # Shared utilities
│   ├── core/           # Feature-based domains (auth, cart, user, etc.)
│   ├── database/       # DB connection & migrations
│   ├── domain/         # Entities & shared errors
│   ├── middleware/     # Custom middlewares
│   └── server/         # Fiber router setup
├── test/integration/   # Repository integration tests
├── docs/               # Swagger documentation
├── Makefile            # Build and development commands
└── go.mod              # Dependencies
```
